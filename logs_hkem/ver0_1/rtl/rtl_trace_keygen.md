# RTL trace 逐函数归因 · ver0_1/keygen

> 方法 A：同一份 app 在 **RTL**（Earlgrey chip sim，OTBN 连真 KMAC）上跑，按 OTBN 指令级 trace 逐拍归因。
> 输入 trace：`logs_hkem/ver0_1/rtl/test_mlkem_keypair_only.rtl_trace.log`（139,298,266 B）。
> 对照口径：ISS 表来自 `logs_hkem/ver0_1_profiling/re_ver0_1.json`（同一份 app）。

## 自证（完整性）

| 判据 | RTL trace | 参照 | 结论 |
|---|---:|---:|---|
| Σ `E`（退休指令） == chip `INSN_CNT` | 511,152 | 511,152 | ✓ |
| Σ (`E`+`S`) + 空档 == trace 跨度 | 541,073 + 17,935 = 559,008 | 跨度 559,008 | ✓ |
| 调用帧实测（`jal`/`jalr`/`ret` 解码建栈） | 455 帧，Σ帧拍 2,128,571 | 含被调、帧间会重复；顶层未闭合帧不计 | ✓ |

## 与 ISS 的差（**信息列**，不是错误）

| 量 | RTL trace | ISS JSON | 差 |
|---|---:|---:|---|
| 退休指令数 | 511,152 | 511,152 | +0（+0.00%） |
| 停滞拍（RTL 的 `S` + 空档 ↔ ISS `stalls`） | 47,856 | 47,869 | -13（-0.03%） |

> 两种口径都已知：① ISS 的 `stalls` 含「取指等待」拍，tracer 的 `S` 只在控制器进入 stall 状态时记录 ⇒ 比对时用 `S`+空档；② 用 KMAC 的版本（ver0_2/ver1_1）ISS 的 KMAC 时序是粗粒度模型 ⇒ 轮询圈数与 RTL 不同，指令数与停滞拍**本就应当有差**。
> trace 里非 `E`/`S` 的行（擦除/寄存器流水账）：2,396,068 行；空档 17,935 拍（无任何记录的拍；按上一条口径，它们与 ISS 的 stalls 同源）。

> 读法：ISS 行的 `cycles` 是 harness 程序里该阶段的 Δ；RTL 列是该函数在**真机**上从进入跑到离开的整段（trace 实测帧，含被调）。两者口径一致 ⇒ 差就是**模型 vs RTL** 的差。
