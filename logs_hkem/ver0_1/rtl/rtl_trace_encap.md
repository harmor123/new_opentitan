# RTL trace 逐函数归因 · ver0_1/encap

> 方法 A：同一份 app 在 **RTL**（Earlgrey chip sim，OTBN 连真 KMAC）上跑，按 OTBN 指令级 trace 逐拍归因。
> 输入 trace：`logs_hkem/ver0_1/rtl/test_mlkem_encap_only.rtl_trace.log`（156,077,952 B）。
> 对照口径：ISS 表来自 `logs_hkem/ver0_1_profiling/re_ver0_1.json`（同一份 app）。

## 自证（完整性）

| 判据 | RTL trace | 参照 | 结论 |
|---|---:|---:|---|
| Σ `E`（退休指令） == chip `INSN_CNT` | 558,624 | 558,624 | ✓ |
| Σ (`E`+`S`) + 空档 == trace 跨度 | 589,886 + 18,262 = 608,148 | 跨度 608,148 | ✓ |
| 调用帧实测（`jal`/`jalr`/`ret` 解码建栈） | 520 帧，Σ帧拍 2,297,620 | 含被调、帧间会重复；顶层未闭合帧不计 | ✓ |

## 与 ISS 的差（**信息列**，不是错误）

| 量 | RTL trace | ISS JSON | 差 |
|---|---:|---:|---|
| 退休指令数 | 558,624 | 558,624 | +0（+0.00%） |
| 停滞拍（RTL 的 `S` + 空档 ↔ ISS `stalls`） | 49,524 | 49,537 | -13（-0.03%） |

> 两种口径都已知：① ISS 的 `stalls` 含「取指等待」拍，tracer 的 `S` 只在控制器进入 stall 状态时记录 ⇒ 比对时用 `S`+空档；② 用 KMAC 的版本（ver0_2/ver1_1）ISS 的 KMAC 时序是粗粒度模型 ⇒ 轮询圈数与 RTL 不同，指令数与停滞拍**本就应当有差**。
> trace 里非 `E`/`S` 的行（擦除/寄存器流水账）：2,600,410 行；空档 18,262 拍（无任何记录的拍；按上一条口径，它们与 ISS 的 stalls 同源）。
