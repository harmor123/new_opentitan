# RTL trace 逐函数归因 · ver1_1/encap

> 方法 A：同一份 app 在 **RTL**（Earlgrey chip sim，OTBN 连真 KMAC）上跑，按 OTBN 指令级 trace 逐拍归因。
> 输入 trace：`logs_hkem/ver1_1/rtl/test_mlkem_encap_only.rtl_trace.log`（39,242,210 B）。
> 对照口径：ISS 表来自 `logs_hkem/ver1_1_profiling/re_ver1_1.json`（同一份 app）。

## 自证（完整性）

| 判据 | RTL trace | 参照 | 结论 |
|---|---:|---:|---|
| Σ `E`（退休指令） == chip `INSN_CNT` | 118,979 | 118,979 | ✓ |
| Σ (`E`+`S`) + 空档 == trace 跨度 | 158,509 + 12,469 = 170,978 | 跨度 170,978 | ✓ |
| 调用帧实测（`jal`/`jalr`/`ret` 解码建栈） | 699 帧（未闭合 0），Σ帧跨度 558,666 | 含被调、帧间会重复；未闭合帧不计 | ✓ |
| **帧跨度 == 帧内记入 + Σ被调帧**（逐帧全等） | 699 帧全等（未闭合 0） | 帧内每拍恰好归属一处 | ✓ |
| 含被调 ≥ 自身拍（叶函数取等） | 全部满足 | 帧跨度定义 | ✓ |

## 与 ISS 的差（**信息列**，不是错误）

| 量 | RTL trace | ISS JSON | 差 |
|---|---:|---:|---|
| 退休指令数 | 118,979 | 118,439 | +540（+0.46%） |
| 停滞拍（RTL 的 `S` + 空档 ↔ ISS `stalls`） | 51,999 | 51,796 | +203（+0.39%） |

> 两种口径都已知：① ISS 的 `stalls` 含「取指等待」拍，tracer 的 `S` 只在控制器进入 stall 状态时记录 ⇒ 比对时用 `S`+空档；② 用 KMAC 的版本（ver0_2/ver1_1）ISS 的 KMAC 时序是粗粒度模型 ⇒ 轮询圈数与 RTL 不同，指令数与停滞拍**本就应当有差**。
> trace 里非 `E`/`S` 的行（擦除/寄存器流水账）：994,552 行；空档 12,469 拍（无任何记录的拍；按上一条口径，它们与 ISS 的 stalls 同源）。

> ¹ **取指等待**=两条记录之间的空拍（fetch 未回），摊给上一条记录所在的函数 —— 与 ISS 的 `has_fetch_stall` 同口径（跳转/循环多出的那一拍记在跳转指令上）。
> 「含被调」= trace 实测**帧跨度** `[C1, C2)`（699 帧，`jal/jalr/ret` 解码建栈；C1 = 进入函数第一拍，C2 = **调用方恢复执行的那一拍**）：帧内每一拍恰好归属一处 ⇒ **叶函数 含被调 == 自身拍**、父函数 = 自身拍 + 帧内兄弟标签 + Σ直接被调含被调（699 帧逐帧核对 `帧跨度 == 帧内记入 + Σ被调帧` ✓）。帧之间仍会重复（被调被父帧包含）⇒ **不能相加**；要「相加等于整段」用自身拍列。
