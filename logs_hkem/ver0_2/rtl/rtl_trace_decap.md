# RTL trace 逐函数归因 · ver0_2/decap

> 方法 A：同一份 app 在 **RTL**（Earlgrey chip sim，OTBN 连真 KMAC）上跑，按 OTBN 指令级 trace 逐拍归因。
> 输入 trace：`logs_hkem/ver0_2/rtl/test_mlkem_decap_only.rtl_trace.log`（93,530,343 B）。
> 对照口径：ISS 表来自 `logs_hkem/ver0_2_profiling/re_ver0_2.json`（同一份 app）。

## 自证（完整性）

| 判据 | RTL trace | 参照 | 结论 |
|---|---:|---:|---|
| Σ `E`（退休指令） == chip `INSN_CNT` | 255,383 | 255,383 | ✓ |
| Σ (`E`+`S`) + 空档 == trace 跨度 | 262,495 + 14,099 = 276,594 | 跨度 276,594 | ✓ |
| 调用帧实测（`jal`/`jalr`/`ret` 解码建栈） | 741 帧（未闭合 0），Σ帧跨度 894,338 | 含被调、帧间会重复；未闭合帧不计 | ✓ |
| **帧跨度 == 帧内记入 + Σ被调帧**（逐帧全等） | 741 帧全等（未闭合 0） | 帧内每拍恰好归属一处 | ✓ |
| 含被调 ≥ 自身拍（叶函数取等） | 全部满足 | 帧跨度定义 | ✓ |

## 与 ISS 的差（**信息列**，不是错误）

| 量 | RTL trace | ISS JSON | 差 |
|---|---:|---:|---|
| 退休指令数 | 255,383 | 255,328 | +55（+0.02%） |
| 停滞拍（RTL 的 `S` + 空档 ↔ ISS `stalls`） | 21,211 | 21,202 | +9（+0.04%） |

> 两种口径都已知：① ISS 的 `stalls` 含「取指等待」拍，tracer 的 `S` 只在控制器进入 stall 状态时记录 ⇒ 比对时用 `S`+空档；② 用 KMAC 的版本（ver0_2/ver1_1）ISS 的 KMAC 时序是粗粒度模型 ⇒ 轮询圈数与 RTL 不同，指令数与停滞拍**本就应当有差**。
> trace 里非 `E`/`S` 的行（擦除/寄存器流水账）：1,639,368 行；空档 14,099 拍（无任何记录的拍；按上一条口径，它们与 ISS 的 stalls 同源）。

> ¹ **取指等待**=两条记录之间的空拍（fetch 未回），摊给上一条记录所在的函数 —— 与 ISS 的 `has_fetch_stall` 同口径（跳转/循环多出的那一拍记在跳转指令上）。
> 「含被调」= trace 实测**帧跨度** `[C1, C2)`（741 帧，`jal/jalr/ret` 解码建栈；C1 = 进入函数第一拍，C2 = **调用方恢复执行的那一拍**）：帧内每一拍恰好归属一处 ⇒ **叶函数 含被调 == 自身拍**、父函数 = 自身拍 + 帧内兄弟标签 + Σ直接被调含被调（741 帧逐帧核对 `帧跨度 == 帧内记入 + Σ被调帧` ✓）。帧之间仍会重复（被调被父帧包含）⇒ **不能相加**；要「相加等于整段」用自身拍列。
